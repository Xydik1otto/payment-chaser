# Payment Chaser — План продукту

## 1. Аудиторія

**Первинна:** фрілансери та solo-бізнеси (дизайнери, розробники, перекладачі,
маркетологи, консультанти), які виставляють 10–100 інвойсів на місяць
і мають 1–5 боржників у будь-який момент.

**Сегменти:**
- українські фрілансери з іноземними клієнтами (двоязычні шаблони uk/en —
  прямо в MVP);
- малі агентства без фінансового відділу;
- виконавці на разових проєктах (авторські договори, поетапні оплати).

**Біль користувача:** «написати нагадування незручно і незважаючи на це
треба» — і через це гроші не вибиваються ніколи.

## 2. Ціннісна пропозиція

«Дебіторка, яка сама себе вибиває». Нагадування перестають бути особистою
незручністю: система пише ввічливо і послідовно, ескалація — за розкладом,
а не за настроєм. Копіпейст-режим (outbox + Copy) прибирає бар'єр входу:
не треба нічого підключати, щоб почати.

## 3. MVP scope (поточна реалізація)

| Функція | Статус |
|---|---|
| Клієнти (ім'я, email, мова uk/en) | ✅ |
| Інвойси: number, client, amount, currency, issued_date, due_date, status draft/sent/overdue/paid | ✅ |
| Движок: обчислює прострочені інвойси, генерує ланцюжок день 1 / 7 / 14 / 30 | ✅ |
| 4 ступені ескалації, кожен спрацьовує один раз, без стрибків через стадії | ✅ |
| Шаблони Jinja2, укр + англ, змінні: клієнт, сума, номер, дні прострочення | ✅ |
| Late fee опція у final notice (`CHASER_LATE_FEE_PERCENT`) | ✅ |
| SMTP-відправка якщо env налаштований, інакше outbox-черга з кнопкою Copy | ✅ |
| Дашборд: кількість прострочених, загальна сума, aging buckets 1-7 / 8-14 / 15-30 / 30+ | ✅ |
| Автопереведення sent → overdue при запуску движка | ✅ |
| UI: одна сторінка HTML + vanilla JS, без build | ✅ |

**Поза MVP:** реєстрація/багатокористувацьість, rebilling/повторні інвойси,
часткові платежі, ledger розсилок (click/open), PDF-інвойси, Stripe/PayPal
посилання «сплатити зараз» у листі, вебхуки, white-label.

## 4. Архітектура

```
Браузер (1 HTML + vanilla JS, fetch API)
   │  JSON over HTTP
FastAPI (app/main.py) ── CRUD, dashboard, engine endpoint
   ├── app/reminder_engine.py ── aging buckets, chain stages,
   │                             "що відправляти сьогодні", рендер Jinja2
   ├── app/mailer.py ── SMTP (env) або outbox-черга
   └── app/db.py ── SQLite: clients, invoices, reminders, outbox
       app/templates/{uk,en}/stage{1..4}.j2
```

- **Движок чистий:** `build_letters(conn, today)` не має side effects —
  тестується на фіксованій даті; відправка — окремий шар `mailer.deliver`.
- **Idempotentність:** стадія пише `reminders` ДО/замість відправки, повторний
  запуск того ж дня не дублює листи.
- **Розгортання:** один процес + SQLite файл; cron викликає `/api/engine/run`.

## 5. Roadmap

| Фаза | Що | Критерій виходу |
|---|---|---|
| MVP (0–1 міс) | інвойси → движок → outbox/SMTP → дашборд | 20 фрілансерів користуються щотижня |
| v1.1 | cron-самозапуск в процессі, статистика «відомо після N листів», часткові платежі | 50% інвойсів оплачені після листа ≤ stage 2 |
| v1.2 | Pay-link у листі (Stripe/Fondy), PDF-прикріплення, мультивалюта курси | перші платні підписки |
| v2.0 | SaaS: реєстрація, команди, white-label підпис | 100 платних клієнтів |

## 6. Монетизація

- **Self-hosted license:** безкоштовне ядро, платна ліцензія на автоматичну
  SMTP-відправку + білий лейбл ($49 одноразово орієнтир).
- **SaaS (пізніше):** $15/міс — до 30 активних інвойсів; $29/міс — безліміт +
  pay-links + відділені бренди. Орієнтир ринку: аналоги на $5–6K MRR
  з 200–300 клієнтів.
- **Success-fee модель** (експеримент): 1% від вибитих сум понад базу —
  вирівнює мотивацію, протестувати на 10 користувачах.

## 7. Ризики

| Ризик | Ймовірність | Мітигація |
|---|---|---|
| Листи потрапляють у спам | висока | outbox-first за замовчуванням, поради щодо SPF/DKIM, відправка з власної пошти користувача (SMTP) |
| Незручно/страшно тиснути «стадію 4» | середня | попередній перегляд тексту, редагування перед відправкою у v1.1 |
| Сезонність/маленький LTV фрілансера | середня | дешевий self-hosted план, додаткові продукти (інвойсинг) |
| Погані боржники: листи не допомагають | висока | чесне позиціонування — «система нагадувань», не колектор; метрики ефективності в дашборді |
| Gmail блокує SMTP-пароли додатків | середня | інструкція App Password, альтернативи (Resend/Brevo) у v1.1 |
| Дублі листів при повторному запуску | низька | idempotentність движка (стадія один раз), покрито тестами |
